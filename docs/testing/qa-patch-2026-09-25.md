# QA Patch Notes — Live Meet / LiveKit Rooms (23–25 Sep 2026)

## Status: Fixed (all 6 reported bugs)

### Bug 1 — Invite link unavailable after room entry
- **Root cause:** Owner received `invitationUrl` at creation, but in-room UI only exposed the room slug.
- **Fix:** Coordinator-only **Copy invite link** builds from `window.location.href` (preserves `?invite=`), strips hash, no DB persistence of raw invite tokens.
- **Evidence:** Unit wording tests + browser CSS/wording probes; manual: Meeting details → Copy invite link.

### Bug 2 — Copied room code cannot join
- **Root cause:** UI labeled slug as “room code,” implying it was a join credential.
- **Fix:** Relabeled to **meeting ID / room identifier**; copy control is “Copy meeting ID”; explicit copy that joining requires invitation link + access code. Admission still rejects missing invite token.
- **Evidence:** `tests/rooms/rejoin.test.js` (slug alone rejected); JoinRoomForm / RoomWorkspace wording tests; browser test for invitation-required copy.

### Bug 3 — Sixth participant cannot rejoin
- **Root cause:** Each first admission consumed `invite.used_count`; no participant-scoped rejoin credential.
- **Fix:** `room_participant_rejoin_grants` (hashed tokens only). First join mints grant + consumes invite; rejoin with invite + access code + rejoin token skips consume. Remove/end revoke grants. Client stores rejoin token in `sessionStorage` by slug.
- **Evidence:** `tests/rooms/rejoin.test.js` (exhaustion, rejoin, remove, end, expiry, cross-room, access code).

### Bug 4 — Shared Prompt wrong editor identity
- **Root cause:** Awareness initialized with `editing: true` for every connected participant.
- **Fix:** Default `editing: false`; `setEditing()`; SharedPromptEditor focus/input/idle(2s)/blur/read-only/unmount.
- **Evidence:** `tests/prompts/editing-presence.test.js`.

### Bug 5 — No visible coordinator indicator
- **Root cause:** Role was server-session only; no UI broadcast.
- **Fix:** Informational LiveKit topic `coordinator_role`; badge in People list + presence/camera tiles. Never used for authorization.
- **Evidence:** Coordinator role client parse test + RoomWorkspace source checks + CSS probes.

### Bug 6 — No promotion notification
- **Root cause:** Notice rendered only inside People drawer.
- **Fix:** Global toast (`role="status"`, ~5s, `data-testid="coordinator-promotion-toast"`), deduped claim tokens, cleared on unmount.
- **Evidence:** RoomWorkspace wording/source test.
